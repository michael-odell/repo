# CLAUDE.md

## Committing

When a change in this repo is complete (builds, tests pass, matches what was
asked), commit it — to whatever branch is currently checked out — with a
commit message in the existing log style (`area: what changed`, e.g. `sync:
...`, `config: ...`, `gitx: ...`; imperative mood, body explaining *why* when
the change isn't self-evident). Don't wait to be asked to commit each time.

Keep unrelated changes in separate commits rather than bundling them.

This does not cover pushing, force-pushing, or rewriting history — those
still need explicit confirmation per the normal safety rules.
